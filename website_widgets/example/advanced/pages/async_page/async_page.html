Async widgets

Any widget's set_context() can be async def and await the async ORM or an HTTP call. The times below are milliseconds since this page started building. Each mock query takes {{ data.query_ms }} ms.

Together

The page's own set_context() runs all three queries at once with asyncio.gather(), then hands each result to an QueryCard through its constructor. They all start and finish at about the same time.

{% for card in children.together %} {{ card }} {% endfor %}

One after another

Each SlowQueryCard awaits its own query in its own set_context(). The library awaits one widget's set_context() before starting the next, so each query waits for the one before it. When several widgets need data, fetch it together in their parent and pass it down.

{% for card in children.one_after_another %} {{ card }} {% endfor %}

Sync widgets

A plain def set_context() is fine for work that doesn't wait. It still runs inside the event loop, though, so a synchronous ORM query there raises SynchronousOnlyOperation. Use the async ORM in an async def set_context().
